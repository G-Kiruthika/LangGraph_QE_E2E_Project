## Access Flow

1. User opens the login page.
2. User enters the demo username `Admin` and Password `admin123`.
3. Successful authentication redirects the session to the dashboard.
4. The dashboard becomes the landing page for daily actions, status widgets, and cross-module shortcuts.

## Dashboard Purpose

The dashboard is the post-login landing page for a signed-in employee or administrator. It aggregates high-frequency HR tasks and status signals into one page so the user can:

- check attendance status and time totals
- review pending workflow items
- jump into common leave and timesheet flows
- see recent internal social posts
- view current leave activity
- understand employee distribution by organization and location

## Dashboard Route Contract

- Entry condition: authenticated session
- Primary page heading: `Dashboard`
- The page is framed by the global OrangeHRM shell: left side navigation, top bar, user menu, and footer.

## Dashboard Information Architecture

The dashboard is composed of widget cards. The observed widgets are:

1. Time at Work
2. My Actions
3. Quick Launch
4. Buzz Latest Posts
5. Employees on Leave Today
6. Employee Distribution by Sub Unit
7. Employee Distribution by Location

These cards mix transactional shortcuts, work-queue indicators, activity feeds, and lightweight analytics.

## Widget Knowledge

### 1. Time at Work

Purpose:

- exposes the current attendance state for the signed-in user
- summarizes today's worked time and the current week's total

Observed fields:

- status label such as `Punched In`
- punch timestamp, for example `Punched In: Today at 06:26 AM (GMT 0)`
- today's duration, for example `0h 20m Today`
- current week label, for example `Sep 14 - Sep 20`
- weekly total, for example `0h 0m`

Observed actions:

- an icon button appears next to the today's duration and next to the weekly summary area, indicating attendance or time-related interaction

Domain interpretation:

- backed by attendance/time-tracking data
- state is user-specific and time-sensitive
- expected to change after punch-in, punch-out, or timesheet events

### 2. My Actions

Purpose:

- surfaces pending items that need the user's direct attention

Observed items:

- `(1) Pending Self Review`
- `(1) Candidate to Interview`

Observed behavior:

- each item appears clickable
- counts are embedded in the label and should be treated as dynamic workflow totals

Domain interpretation:

- this widget is a personalized task inbox spanning multiple modules such as performance and recruitment
- items are conditional on role, assignments, and current workflow state

### 3. Quick Launch

Purpose:

- provides one-click entry points into common HR tasks

Observed shortcuts:

- Assign Leave
- Leave List
- Timesheets
- Apply Leave
- My Leave
- My Timesheet

Domain interpretation:

- shortcuts bridge directly into leave and time-management workflows
- the set is action-oriented rather than analytics-oriented
- these actions likely navigate to forms or filtered lists in the Leave and Time domains

### 4. Buzz Latest Posts

Purpose:

- shows recent internal social or announcement posts from the Buzz module

Observed post structure:

- author name
- post timestamp
- post text content
- optional media attachment/image

Observed sample content patterns:

- congratulatory announcement
- long-form discussion post
- short status/update post
- post with image attachment

Domain interpretation:

- this is a recency-ordered feed preview
- entries appear to link back to the author/post context
- dashboard acts as a read-only teaser surface for deeper Buzz activity

### 5. Employees on Leave Today

Purpose:

- highlights who is currently out on leave

Observed row structure:

- employee avatar
- employee display name
- leave descriptor such as region/type or leave category
- employee identifier shown at the row end

Observed examples:

- `CAN - Matternity (Half Day - Morning)`
- `US - Personal`

Observed behavior:

- an info or expand icon is present in the card header

Domain interpretation:

- this widget is organization-aware, date-bound, and likely filtered to the current day
- useful for operational visibility and staffing awareness

### 6. Employee Distribution by Sub Unit

Purpose:

- provides an organizational breakdown by department or sub unit

Observed categories:

- Engineering
- Human Resources
- Administration
- Client Services
- Unassigned

Observed behavior:

- each category is rendered as a clickable list item

Domain interpretation:

- represents aggregated employee counts by organizational hierarchy
- `Unassigned` indicates data quality or onboarding gaps where a user lacks a mapped sub unit

### 7. Employee Distribution by Location

Purpose:

- provides an organizational breakdown by location

Observed categories:

- Texas R&D
- New York Sales Office
- Unassigned

Observed behavior:

- each category is rendered as a clickable list item

Domain interpretation:

- represents aggregated employee counts by physical or business location
- `Unassigned` indicates missing location mapping on employee records

## Behavioral Notes

- The dashboard is heavily role-sensitive. Widget content and counts should be expected to vary by user permissions and assigned work.
- Several widgets are data snapshots rather than primary record-management screens.
- The page blends personal data, organization data, and navigation shortcuts in one layout.
- Counts, timestamps, and feed content are dynamic and should not be treated as fixed fixtures.
- `Unassigned` values are domain-significant because they expose incomplete master data.
